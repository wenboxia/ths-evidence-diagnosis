## 1. 一句话产品定义

不给“好/坏”标签，也不给买卖建议。产品把一家公司的当前状态拆成一组**可回溯的证据**，分为正面、负面、矛盾、未知四类，再由 Agent 针对用户的问题组织解读。解读中的每一句话都必须引用证据，并经过校验器检查。

## 2. 产品选择：为什么是这道题、这只股票

- **为什么选“个股多维诊断与证据验证”**：AIME 的核心挑战是“金融长任务的回答真实性、工具执行稳定性和可溯源”。这道题天然要求三件事同时成立：确定性计算与 LLM 解读分工、结论可追溯到原始字段、数据缺失或失败时不能静默给出正常结论。它最能完整展示规划、工具调用、校验、反思和降级这一整条 Agent 链路，也和 AIME 中投研分析、财报解读、风险提示等技能的日常工作最接近。
- **为什么选同花顺（300033）**：它的收入与 A 股成交活跃度高度相关，可以演示“按公司类型选择诊断维度”（专属的“经营驱动”维度）；扶摇对它的财务、估值、行情覆盖完整；同行池清晰（东方财富、指南针、大智慧、财富趋势）。其中东方财富的券商口径不可比，正好用来检验“数据冲突”的处理。
- **为什么加贵州茅台作为对照**：茅台是非顺周期的消费品牌。切换后“经营驱动”维度消失、维度优先级改变，用来验证维度选择确实由公司类型驱动，而不是写死的。

## 3. 目标用户与场景

| 用户 | 场景 | 现有方式的痛点 |
|---|---|---|
| 有一定经验的个人投资者 | 看到一只股票想快速了解“现在是什么状态” | F10 信息全但要自己拼；AI 问答很流畅，但数字从哪来、是否过期都不知道 |
| 投研新人 / 财经内容作者 | 需要一份“结论 + 证据 + 待验证事项”的研究底稿 | 结论和依据分离，追溯原始数据费时 |

核心任务：**弄清这家公司现在怎么样，哪些是事实、哪些是推断、哪些还不知道，下一步该查什么。**

## 4. 核心设计：确定性证据层 + Agent 解读层 + 校验层

```
用户问题 ──► ① 规划器(LLM，规则兜底) ──► 选择诊断维度 + 合规改写
                                         │
扶摇 API ──► ② 数据工具层(24 次调用) ──► ③ 证据层(确定性代码) ──► 证据看板（不依赖 LLM，先出）
             探测熔断/超时/限流重试/         计算指标、判定正负、同行     正面 / 负面 / 矛盾 / 未知
             总时限/快照回退，如实记录       合理性检查、矛盾识别、       + 风险规则清单（15 项，含未触发）
                                             风险规则检查、待验证问题     + 待验证问题
                                         │
                                         ▼
                              ④ 解读器(LLM) 只能引用证据 ID
                                         │
                              ⑤ 校验器(确定性) ── 未通过 ──► ⑥ 反思：只把未通过的陈述 + 校验意见交给 LLM 定点修复
                                         │                        │仍未通过：标注 ⚠；合规问题隐去原文；删除的陈述计数并说明原因
                                         ▼
                              结构化输出：回应 / 分维度要点 / 矛盾 / 未知 / 沿证据继续研究
```

### 职责边界（这个分工是本产品的核心）

| 角色 | 负责 | 不负责 |
|---|---|---|
| **数据工具层** `lib/fuyao.js` `lib/collect.js` | 调用扶摇接口；超时、限流退避、总时限控制；如实记录每次调用（接口、参数、request_id、耗时、数据时点） | 不做任何判断 |
| **证据层** `lib/evidence.js` | **所有数字都在这里计算**：同比、毛利率、现金含量、波动、回撤、相对收益、同行排名、相关系数；按写明的规则判定正/负；识别矛盾组合；数据缺失、冲突、过期时生成“未知”而非结论 | 不写自然语言判断 |
| **LLM（规划器）** `lib/agent.js#llmPlan` | 理解问题意图，结合公司类型选择 3–6 个维度并说明理由；识别买卖/涨跌类问题并改写为客观维度。规划输出的文字同样要过合规检查，命中禁用词就替换为规则文本。“全面诊断”（问题为空）时由规则直接覆盖全部维度 | 不能决定数据从哪来 |
| **LLM（解读器）** `lib/agent.js#llmInterpret` | 用自然语言组织证据；区分事实与推断（推断需带置信度）；并列呈现矛盾；提出待验证问题 | 不能产生证据之外的数字，不能给买卖建议 |
| **校验器** `lib/agent.js#verify` | 不把 LLM 自报的内容当真：检查引用存在；陈述中的数字须能在所引证据中找到（正则比对，有局限）；缺失、失败或冲突的数据不能被当作结论；措辞方向须与证据的规则判定一致；合规与标签禁用词；含评价性措辞的“事实”**确定性改判为推断** | 无法保证推断在逻辑上一定正确 |

### “根据公司类型选择诊断维度”

证据层先根据数据给公司画像（`profileCompany`），画像决定维度的默认优先级，规划器再结合用户问题调整：

- **同花顺 → 轻资产金融信息服务（顺周期）**：依据为毛利率 91.5%、研发费用率 19%、收入受市场活跃度驱动。因此**新增专属维度“经营驱动”**：把两市成交额（上证 + 深证）按报告期对齐，计算它与营收同比的相关性（D1），并统计财报期后至今成交额的同比变化（D2），作为下一期业绩的环境信号（属于事实层，传导效果需财报验证）。
- **贵州茅台 → 一般工商业 / 高毛利消费**：没有市场活跃度维度，优先看经营质量与财务趋势。
- 若公司负债率 > 80%（类金融），画像变为“金融/类金融”：资产负债率证据（Q5）的判定改为中性并注明原因，维度优先级中估值（PB）靠前。
- 画像中的每个特征都标注依据和数值，例如“高毛利（91.5%）[Q1]”。同花顺的“收入受市场活跃度驱动”属于行业属性预设，页面会如实标注数据支持的强弱（当前 D1 相关系数 r=0.50，低于 0.6 的强相关线，标为“数据支持较弱”）。

## 5. 证据模型（关键数字为什么可追溯）

每条证据（如 `F1 2026中报营业收入同比 +48.68%`）都带有：

| 字段 | 示例 |
|---|---|
| 取值 / 明细 | +48.68%；26.46 亿元（上年同期 17.79 亿元） |
| 报告期 / 区间 | 2026 中报 |
| 口径 | 合并报表；季报为**年初至报告期末累计值**（已用“Q4 季报 = 年报”自动交叉验证） |
| 判定与规则 | 正面；规则：同比 ≥10% 记正面，<0 记负面 |
| 计算公式 | (本期 operating_income − 上年同期) / \|上年同期\| |
| 原始来源 | `/api/a-share/financials/income-statements`，参数，字段 `operating_income`，request_id，抓取时间 |
| 钻取 | 财务期次表（高亮所用字段）、行情区间图（1 月至 3 年可切换，叠加基准）、同行对比表、驱动因子对齐表 |

证据状态分五种：
- `ok`：正常。
- `stale`：可能过期，指最新 K 线距今超过 7 个自然日（长假休市属正常），或实时调用失败后使用了快照/缓存。stale 证据**仍按规则判定并参与矛盾和风险识别**，但每处都标注“基于快照/过期数据”，AI 解读区顶部也会统一提示。
- `missing`：缺字段（字段为空时不会算出 0% 之类的假值）或数据源不提供。
- `error`：调用失败。
- `conflict`：数据冲突，包括两个来源不一致（报表算出的毛利率与指标接口偏差超过 1pct，X1），以及同行口径不可比（净利率不在 ±100% 之间或净利大于营收，X2）。

后三种（missing、error、conflict）一律进入“未知”栏，不参与正负判定，并自动生成待验证问题。

风险维度采用**规则清单**（`risk_checks`，共 15 项，含 4 项数据风险；不适用于该公司类型的规则标为“不适用”），每一项都会检查：已触发的进入风险栏，未触发的折叠展示。这样“风险为空”不会被误读为“没有检查过”。

## 6. 数据来源与使用

全部来自 **同花顺扶摇金融数据 API**（`https://fuyao.aicubes.cn`，请求头 `X-api-key`）。单次诊断约 24 次调用，4 路并发，总时限 40s：

| 维度 | 接口 | 用途 |
|---|---|---|
| 财务趋势 / 经营质量 | `/api/a-share/financials/income-statements`、`balance-sheets`、`cash-flow-statements`（年 + 季） | 同比、CAGR、毛利率、费用率、现金含量、ROE、负债率、应收增速 |
| 交叉校验 | `/api/a-share/financials/indicators` | 指标接口与报表计算值双源比对 |
| 估值 | `/api/a-share/valuations/snapshot` | PE/PB/PS/PCF 及同行中位数（仅取正值） |
| 行情特征 | `/api/a-share/prices/historical`（前复权日 K，3 年） | 区间涨跌、波动、回撤、52 周位置、成交活跃度 |
| 相对表现 / 经营驱动 | `/api/a-share-index/prices/historical`（创业板指、沪深300；上证指数 + 深证综指 = 两市全部成交额） | 超额收益、两市成交额 |
| 行业位置 | 同行利润表、估值快照、财务指标 | 同一报告期排名 |
| 重要事件 | `corporate-actions/adjustment-factors`、`special-data/anomaly-analysis-stock`、`special-data/hot-stock-rank-trend` | 分红、当日异动原因（标注为“观点”）、热榜关注度 |

**未使用 / 无法使用的数据**（在产品中显式列为“未知”）：
- 扶摇“资讯事件库”标注为仅限同花顺 AI 客户端使用。**iFinD MCP 未接入**：它可以提供公告、新闻和政策数据，但需要 iFinD 账号授权，本次没有取得。因此公告、新闻、研报原文无法核验（证据 E9，页面标为“未接入”，并给出巨潮资讯网的验证路径）；市场宽度、资金、宏观类数据也没有纳入。
- 上年同期的财报数据：接口返回的 `report_date_ms` 可能晚于其报告期（例如 2025 中报显示 2026-08-22 披露）。这说明该值取自较新的披露版本，可能是追溯调整后的比较数据。同比计算使用这一口径，并在证据口径和财务表脚注中注明。
- 估值接口只提供最新快照，**无历史估值分位**。产品不推算分位，而是列为待验证问题。
- 财报不含分部收入。“哪块业务对市场活跃度最敏感”列为待验证问题，并给出年报查阅路径。
- 同行池为**人工选取**（扶摇“股票所属同花顺指数查询”接口尚未开放），选取规则在页面上写明。

## 7. 失效模式与降级（对应 JD 中“容错、恢复、重试”）

| 失效 | 处理 | 用户看到什么 |
|---|---|---|
| 扶摇限流（HTTP 429 / code 4001）、上游超时（5002/5003）、网络错误 | 退避后重试 1 次 | 调用记录中显示重试次数 |
| 鉴权 / 权限 / 参数 / 标的不存在等业务错误（2001、2003、1002、3001…） | 不重试、**不回退快照**，直接记录 | 对应证据进入“未知”，原因写明错误码 |
| 数据源连接层失败（网络、超时、限流、上游 5xx） | 6s 探测熔断；只对这类可恢复错误回退到快照或缓存 | 横幅显示熔断原因；证据标“可能过期”，并写明抓取时间 |
| 单个字段为空 | 计算前逐字段检查，走 `missing` | 不会出现“资产负债率 0.00%”这类假值 |
| 同行财务口径不可比（如券商的营收字段） | 合理性检查，标为 X2 冲突；只从依赖营收的排名中剔除；排名不完整时不判正负 | 同行表标注“口径不可比”，并生成待验证问题 |
| 响应体传输卡住 | 超时计时覆盖到 body 读取 | 判为超时，不会让整个请求挂起 |
| 采集总时长超过 40s | 剩余调用标记为 `BUDGET` | 部分证据“未知”，其余正常展示 |
| 依赖缺失（拿不到最新报告期） | 跳过财务指标调用，并说明原因 | 不会用猜测的报告期去取数 |
| 两个数据源冲突 | 证据标为 `conflict` | 相关结论降级为待验证 |
| 行情过期 / 使用快照 | 证据标为 `stale`，仍参与矛盾和风险判断 | 页头、横幅、解读区顶部、每条证据都有提示 |
| 主 LLM 超时、报错或输出空/非 JSON | 自动切换供应商：DeepSeek → GLM（快）→ Kimi，并为后续供应商预留时间 | 轨迹中显示每次尝试 |
| 全部 LLM 不可用 | 规划用规则兜底，解读用**仅含事实的模板** | 明确标注“AI 解读不可用，仅展示事实” |
| LLM 编造数字、引用不存在的证据、读反方向、给买卖建议、贴好坏标签 | 校验器拦截 → **定点修复**：只把未通过的陈述和校验意见交给 LLM 修改，修复后再校验一次（比整篇重写快，实测约 3s） | 仍未通过的句子旁显示“⚠ 未通过校验”；合规问题**隐去原文**；修复时删掉的陈述在校验报告中计数，并写明位置和原因 |
| LLM 把推断标成事实 | “事实”中出现评价、因果或比较类措辞（偏高、强劲、意味、可能、主要来自、弹性……），或引用了派生/观点类证据时，确定性改判为推断；type 缺失时也按推断处理 | 陈述旁注明“系统改判” |
| LLM 把已有数据说成“没有” | 规则命中的维度必须保留；解读时提供全部风险规则所引用的证据；校验器识别“未提供/无法评述”这类说法，并核对所引证据是否真的缺失 | 判为严重问题，定点修复 |
| 问答时重复取数（数据源压力大、耗时长） | 问答接口复用前端已拿到的诊断结果，用服务端 **HMAC 签名**防篡改；签名无效或超过 30 分钟则重新采集 | 轨迹更快；被篡改的证据不会被采用 |

## 8. 合规设计

- 规划器识别“能买吗 / 会涨吗 / 目标价”等意图，即使 LLM 漏判，也会用规则兜底，并在页面上显示合规提示，改为呈现估值、业绩趋势、风险等客观维度。
- 解读器的系统提示禁止买卖建议、目标价、涨跌预测、收益承诺和好坏标签；校验器再用正则拦截一次。词表按**短语**匹配：只拦“继续持有、建议观望、将反弹、有望见底”这类操作建议和预测，不拦“持有货币资金、业务布局、股价曾反弹、高估值意味着……”这类中性陈述（有回归测试覆盖两类）。词表覆盖：买卖与持仓操作（加仓、建仓、持有、观望、止损、追高、买点）、涨跌预测（会上涨、上升空间、有望修复、见底、反弹、拐点）、收益与价值判断（收益可期、投资价值、安全边际、性价比、估值洼地），以及好坏标签（好公司、优秀公司、优质、白马、低估高估、便宜、护城河、前景广阔）。
- 否定豁免只认同一分句内的固定短语（不提供、不构成、不给出、无法判断、不代表），例如“本产品不提供买入、持有或卖出建议”。“不建议卖出，可继续持有”“这并非卖出时机”这类隐含操作建议的说法**不豁免**。
- 校验报告和轨迹返回前端前，会去掉违规原文，只保留位置、类型和原因。
- 规划器输出的文字（意图、维度理由、合规说明、追问）同样过合规检查。修复后仍违规的句子会隐去原文。
- 正负判定只用于单条证据，页头的条数旁注明“条数不代表权重，不构成综合评价”。
- 异动原因、热榜等**观点 / 情绪类信息**单独标注，不参与正负判定。
- 页面底部有常驻免责声明；API Key 只存在于服务端环境变量。

## 9. 如果这是 AIME 的一个技能：评测与指标设计（本版已埋点，未做看板）

| 指标 | 定义 | 当前采集位置 |
|---|---|---|
| 任务完成率 | 有完整解读输出的会话 / 总会话（模板降级单独统计） | `trace`、`mode` |
| 引用覆盖率 | 带有效证据引用的陈述 / 全部陈述 | `verify().statements / issues` |
| 首次校验通过率、重写挽回率 | 第一次即通过的比例；重写后通过的比例 | `trace` 中的 verify / reflect 步骤 |
| 幻觉拦截数 | `unsupported_number`、`bad_citation`、`direction_mismatch` 的命中数 | `verification.issues` |
| 工具失败率 / 降级率 | 失败调用 / 总调用；`fallback` 步骤占比 | `calls`、`trace` |
| 合规触发率 | 合规改写或拦截次数 | `plan.compliance`、`compliance` issue |
| 端到端延迟 | 采集、规划、解读各阶段耗时 | `calls[].latency_ms`、`trace[].latency_ms` |

## 10. 启动方式

```bash
cp .env.example .env      # 填入 FUYAO_API_KEY 与至少一个 LLM Key
npm run dev               # http://localhost:3000 ，无需安装依赖（Node ≥ 18）
```

在某些代理环境下，Node 内置的 fetch 不读取系统代理，需要加上 `NODE_USE_ENV_PROXY=1`（Node ≥ 24）。

## 12. 已知边界

- 只支持两只预设标的。同行池和公司专属驱动因子依赖人工配置；扩展到全市场需要“个股所属行业指数”接口（扶摇标注“敬请期待”）。
- 证据正负判定的阈值（如营收同比 ≥10% 记正面）是**通用经验值**，没有按行业校准。规则在每条证据上公开，便于质疑。
- 季报为累计口径，没有拆出单季度数据，因此单季环比变化无法判断（已列为未知）。
- 市场活跃度相关性只有约 6 个报告期样本，仅作描述，不代表因果。
- 校验器能拦截数字、引用、方向和合规问题，但**无法保证推断在逻辑上是对的**。数字校验是正则比对，存在局限，例如无法识别中文数字。推断与事实用徽标区分（事实 / 推断·置信度），不是物理上分栏展示。
- 正负判定的规则词表和合规词表都是经验性的，可能误报或漏报。误报会触发定点修复；漏报只能靠提示词约束兜底。
- 服务端缓存只在实例内存中保留 10 分钟；冷启动时会重新采集（实测 3–5s）。
- **扶摇对云服务器 IP 存在间歇性连接超时**（原因未知，推测为频控/风控）。熔断后展示的是部署时的快照，所有证据都会标注“可能过期”和抓取时间；快照不会自动更新，需要重新运行 `scripts/snapshot.js` 并重新部署。
- `*.vercel.app` 在部分国内网络下访问可能不稳定。
