## 1. 一句话产品定义

不给“好/坏”标签，也不给买卖建议。产品把一家公司的当前状态拆成一组**可回溯的证据**，分为正面、负面、矛盾、未知四类，再由 Agent 针对用户的问题组织解读。解读中的每一句话都必须引用证据，并经过校验器检查。

## 2. 目标用户与场景

| 用户 | 场景 | 现有方式的痛点 |
|---|---|---|
| 有一定经验的个人投资者 | 看到一只股票想快速了解“现在是什么状态” | F10 信息全但要自己拼；AI 问答很流畅，但数字从哪来、是否过期都不知道 |
| 投研新人 / 财经内容作者 | 需要一份“结论 + 证据 + 待验证事项”的研究底稿 | 结论和依据分离，追溯原始数据费时 |

核心任务：**弄清这家公司现在怎么样，哪些是事实、哪些是推断、哪些还不知道，下一步该查什么。**

## 3. 核心设计：确定性证据层 + Agent 解读层 + 校验层

```
用户问题 ──► ① 规划器(LLM，规则兜底) ──► 选择诊断维度 + 合规改写
                                         │
扶摇 API ──► ② 数据工具层(24 次调用) ──► ③ 证据层(确定性代码) ──► 证据看板（不依赖 LLM，先出）
             探测熔断/超时/限流重试/         计算指标、判定正负、       正面 / 负面 / 矛盾 / 未知
             总时限/快照回退，如实记录       识别矛盾、生成待验证问题
                                         │
                                         ▼
                              ④ 解读器(LLM) 只能引用证据 ID
                                         │
                              ⑤ 校验器(确定性) ── 未通过 ──► ⑥ 带校验意见反思重写(1 次)
                                         │                        │仍未通过：在原句旁显式标注
                                         ▼
                              结构化输出：回应 / 分维度要点 / 矛盾 / 未知 / 沿证据继续研究
```

### 职责边界（这个分工是本产品的核心）

| 角色 | 负责 | 不负责 |
|---|---|---|
| **数据工具层** `lib/fuyao.js` `lib/collect.js` | 调用扶摇接口；超时、限流退避、总时限控制；如实记录每次调用（接口、参数、request_id、耗时、数据时点） | 不做任何判断 |
| **证据层** `lib/evidence.js` | **所有数字都在这里计算**：同比、毛利率、现金含量、波动、回撤、相对收益、同行排名、相关系数；按写明的规则判定正/负；识别矛盾组合；数据缺失、冲突、过期时生成“未知”而非结论 | 不写自然语言判断 |
| **LLM（规划器）** `lib/agent.js#llmPlan` | 理解问题意图，结合公司类型选择 3–6 个维度并说明理由；识别买卖/涨跌类问题并改写为客观维度 | 不能决定数据从哪来 |
| **LLM（解读器）** `lib/agent.js#llmInterpret` | 用自然语言组织证据；区分事实与推断（推断需带置信度）；并列呈现矛盾；提出待验证问题 | 不能产生证据之外的数字，不能给买卖建议 |
| **校验器** `lib/agent.js#verify` | 不信任 LLM：检查引用存在、数字可在所引证据中找到、缺失数据未被当作结论、措辞方向与证据判定一致、合规禁用词 | — |

### “根据公司类型选择诊断维度”

证据层先根据数据给公司画像（`profileCompany`），画像决定维度的默认优先级，规划器再结合用户问题调整：

- **同花顺 → 轻资产金融信息服务（顺周期）**：依据为毛利率 91.5%、研发费用率 19%、收入受市场活跃度驱动。因此**新增专属维度“经营驱动”**：把两市成交额（上证 + 深证）按报告期对齐，计算它与营收同比的相关性（D1），并统计财报期后至今成交额的同比变化（D2），作为下一期业绩的环境信号（属于事实层，传导效果需财报验证）。
- **贵州茅台 → 一般工商业 / 高毛利消费**：没有市场活跃度维度，优先看经营质量与财务趋势。
- 若公司负债率 > 80%（类金融），资产负债率的正负规则会自动失效，PB 的优先级提升。

## 4. 证据模型（关键数字为什么可追溯）

每条证据（如 `F1 2026中报营业收入同比 +48.68%`）都带有：

| 字段 | 示例 |
|---|---|
| 取值 / 明细 | +48.68%；26.46 亿元（上年同期 17.79 亿元） |
| 报告期 / 区间 | 2026 中报 |
| 口径 | 合并报表；季报为**年初至报告期末累计值**（已用“Q4 季报 = 年报”自动交叉验证） |
| 判定与规则 | 正面；规则：同比 ≥10% 记正面，<0 记负面 |
| 计算公式 | (本期 operating_income − 上年同期) / \|上年同期\| |
| 原始来源 | `/api/a-share/financials/income-statements`，参数，字段 `operating_income`，request_id，抓取时间 |
| 钻取 | 财务期次表（高亮所用字段）、行情区间图（1 月至 3 年可切换，叠加基准）、同行对比表、驱动因子对齐表 |

证据状态分五种：`ok`、`stale`（行情超过 5 天未更新）、`missing`（缺字段或数据源不提供）、`error`（调用失败）、`conflict`（两个来源不一致，例如报表算出的毛利率与指标接口的毛利率偏差超过 1pct）。**后三种一律进入“未知”栏，不参与正负判定**，并自动生成待验证问题。

## 5. 数据来源与使用

全部来自 **同花顺扶摇金融数据 API**（`https://fuyao.aicubes.cn`，请求头 `X-api-key`）。单次诊断约 24 次调用，4 路并发，总时限 40s：

| 维度 | 接口 | 用途 |
|---|---|---|
| 财务趋势 / 经营质量 | `/api/a-share/financials/income-statements`、`balance-sheets`、`cash-flow-statements`（年 + 季） | 同比、CAGR、毛利率、费用率、现金含量、ROE、负债率、应收增速 |
| 交叉校验 | `/api/a-share/financials/indicators` | 指标接口与报表计算值双源比对 |
| 估值 | `/api/a-share/valuations/snapshot` | PE/PB/PS/PCF 及同行中位数（仅取正值） |
| 行情特征 | `/api/a-share/prices/historical`（前复权日 K，3 年） | 区间涨跌、波动、回撤、52 周位置、成交活跃度 |
| 相对表现 / 经营驱动 | `/api/a-share-index/prices/historical`（创业板指、沪深300、上证指数、深证成指） | 超额收益、两市成交额 |
| 行业位置 | 同行利润表、估值快照、财务指标 | 同一报告期排名 |
| 重要事件 | `corporate-actions/adjustment-factors`、`special-data/anomaly-analysis-stock`、`special-data/hot-stock-rank-trend` | 分红、当日异动原因（标注为“观点”）、热榜关注度 |

**未使用 / 无法使用的数据**（在产品中显式列为“未知”）：
- 扶摇“资讯事件库”标注为仅限同花顺 AI 客户端使用；本次未接入 iFinD MCP。因此公告、新闻、研报原文无法核验（证据 E9）。
- 估值接口只提供最新快照，**无历史估值分位**。产品不推算分位，而是列为待验证问题。
- 财报不含分部收入。“哪块业务对市场活跃度最敏感”列为待验证问题，并给出年报查阅路径。
- 同行池为**人工选取**（扶摇“股票所属同花顺指数查询”接口尚未开放），选取规则在页面上写明。

## 6. 失效模式与降级（对应 JD 中“容错、恢复、重试”）

| 失效 | 处理 | 用户看到什么 |
|---|---|---|
| 扶摇限流（HTTP 429 / code 4001）、上游超时（5002/5003）、网络错误 | 退避后重试 1 次 | 调用记录中显示重试次数 |
| 鉴权 / 参数 / 标的不存在等业务错误 | 不重试，直接记录 | 对应证据进入“未知”，原因写明错误码 |
| 响应体传输卡住 | 超时计时覆盖到 body 读取 | 判为超时，不会让整个请求挂起 |
| 采集总时长超过 40s | 剩余调用标记为 `BUDGET` | 部分证据“未知”，其余正常展示 |
| 依赖缺失（拿不到最新报告期） | 跳过财务指标调用，并说明原因 | 不会用猜测的报告期去取数 |
| 两个数据源冲突 | 证据标为 `conflict` | 相关结论降级为待验证 |
| 行情过期 | 证据标为 `stale` | 横幅 + 风险栏提示“数据可能过期” |
| 主 LLM 超时、报错或输出空/非 JSON | 自动切换供应商：DeepSeek → Kimi → GLM | 轨迹中显示每次尝试 |
| 全部 LLM 不可用 | 规划用规则兜底，解读用**仅含事实的模板** | 明确标注“AI 解读不可用，仅展示事实” |
| LLM 编造数字、引用不存在的证据、读反方向、给买卖建议 | 校验器拦截 → **定点修复**：只把未通过的陈述和校验意见交给 LLM 修改，修复后再校验一次（比整篇重写快，实测约 3s） | 仍未通过的句子旁显示“⚠ 未通过校验”，**不静默删除** |
| 问答时重复取数（数据源压力大、耗时长） | 问答接口复用前端已拿到的诊断结果，用服务端 **HMAC 签名**防篡改；签名无效或超过 30 分钟则重新采集 | 轨迹更快；被篡改的证据不会被采用 |

## 7. 合规设计

- 规划器识别“能买吗 / 会涨吗 / 目标价”等意图，即使 LLM 漏判，也会用规则兜底，并在页面上显示合规提示，改为呈现估值、业绩趋势、风险等客观维度。
- 解读器的系统提示禁止买卖建议、目标价、涨跌预测、收益承诺和好坏标签；校验器用正则做二次拦截。
- 异动原因、热榜等**观点 / 情绪类信息**单独标注，不参与正负判定。
- 页面底部有常驻免责声明；API Key 只存在于服务端环境变量。

## 9. 启动方式

```bash
cp .env.example .env      # 填入 FUYAO_API_KEY 与至少一个 LLM Key
npm run dev               # http://localhost:3000 ，无需安装依赖（Node ≥ 18）
npm test                  # node:test 自动化测试（使用构造数据，不需要任何 Key）
node scripts/snapshot.js  # 生成“最近一次成功采集快照”到 snapshots/（不入库，随 Vercel 部署打包，用于熔断回退）
MOCK_DATA=1 npm run dev   # 构造数据模式（页面顶部会显著标注“构造数据”）
```

在某些代理环境下，Node 内置的 fetch 不读取系统代理，需要加上 `NODE_USE_ENV_PROXY=1`（Node ≥ 24）。

### 环境变量

| 变量 | 说明 |
|---|---|
| `FUYAO_API_KEY` | 扶摇 API Key（必填） |
| `LLM_API_KEY` / `LLM_BASE_URL` / `LLM_MODEL` | 主 LLM，任意 OpenAI 兼容接口；默认 DeepSeek `deepseek-flash`（V4.1 Flash） |
| `KIMI_API_KEY` / `KIMI_MODEL` | 备用 LLM 1（默认 `kimi-k3`） |
| `GLM_API_KEY` / `GLM_MODEL` | 备用 LLM 2（默认 `glm-5.3-flash`） |
| `MOCK_DATA` | 设为 `1` 时使用构造数据 |

### 部署

Vercel：`api/*.js` 为 Serverless Function，`public/` 为静态页面，区域 `sin1`，函数时限 60s。Key 通过 `vercel env add` 注入，不进入仓库；`snapshots/` 通过 `.vercelignore` + `includeFiles` 随函数部署，但被 `.gitignore` 排除在公开仓库之外。

## 10. 代码结构

```
api/diagnose.js     GET  采集 + 证据（确定性部分，先出）

tests/              node:test 自动化测试
```

## 11. 已知边界

- 只支持两只预设标的。同行池和公司专属驱动因子依赖人工配置；扩展到全市场需要“个股所属行业指数”接口（扶摇标注“敬请期待”）。
- 证据正负判定的阈值（如营收同比 ≥10% 记正面）是**通用经验值**，没有按行业校准。规则在每条证据上公开，便于质疑。
- 季报为累计口径，没有拆出单季度数据，因此单季环比变化无法判断（已列为未知）。
- 市场活跃度相关性只有约 6 个报告期样本，仅作描述，不代表因果。
- 校验器能拦截数字、引用、方向和合规问题，但**无法保证推断在逻辑上是对的**。推断一律标注为“推断 + 置信度”，并与事实分开展示。
- 服务端缓存只在实例内存中保留 10 分钟；冷启动时会重新采集（实测 3–5s）。
- **扶摇对云服务器 IP 存在间歇性连接超时**（原因未知，推测为频控/风控）。熔断后展示的是部署时的快照，所有证据都会标注“可能过期”和抓取时间；快照不会自动更新，需要重新运行 `scripts/snapshot.js` 并重新部署。
- `*.vercel.app` 在部分国内网络下访问可能不稳定。
