| 环节 | AI 做了什么 | 我（候选人）做的判断与决策 |
|---|---|---|

| 实现 | 编写全部代码 | 逐项验收：真实数据联调、线上部署验证、手工核对关键数字 |
| 测试 | 子 agent 按测试矩阵写测试 | 设计测试矩阵：主链路、接口失败、限流、超时、数据冲突、过期、合规、校验器、LLM 降级 |

## 3. 修正过的错误与不合理结果（按发现顺序）

| # | 现象 | 根因 | 修正 |
|---|---|---|---|
| 1 | 设计初期计划用资讯库做“重要事件”维度 | 读文档发现扶摇资讯事件库仅在同花顺 AI 客户端内提供 | 改用分红、异动原因、热榜、财报披露日；公告/新闻原文列为未知 E9，并给出验证路径 |
| 2 | 本地第一次跑真实数据，**21 个调用全部失败** | 本地 Node fetch 没走代理（环境问题） | 用 `NODE_USE_ENV_PROXY=1` 解决。同时借此**验证了失败路径**：全部失败时 0 条正面/负面结论，全部进入“未知”，没有生成任何“正常”结论 |
| 3 | DeepSeek Flash 返回空内容 | 该模型默认带推理，`max_tokens=300` 被推理过程耗尽 | 调大 max_tokens；把“空输出”识别为一种失败，触发供应商切换 |
| 4 | Kimi k3 报 `invalid temperature` | 该模型只允许 temperature=1 | 为每个供应商单独配置参数 |
| 5 | **LLM 把正面证据读反**：应收账款 −5.5%、营收 +48.7%，被写成“回款未随收入扩张” | 校验器只查数字和引用，查不出方向错误 | ① 给 LLM 的证据增加 `judged_as` 与 `rule`；② 校验器新增 `direction_mismatch`：所引证据全为正面、措辞却偏负面（或反之）且没有转折词时，判为严重问题，触发重写 |
| 6 | 校验器误报：LLM 引用“未达 0.6 强相关阈值”“未触发 >50% 波动”被判为数字无依据 | 校验时只比对了证据的取值文本，没比对判定规则文本 | 判定规则文本也纳入可支撑数字的范围 |
| 7 | **线上 `/api/diagnose` 偶发 504（60s 超时）** | 超时计时器在收到响应头后就被清除，响应体传输卡住时请求会无限挂起 | 超时覆盖到 body 读取；增加 40s 采集总时限，超时的调用标记为 `BUDGET` 并降级。修复后线上连续请求 4–5s |
| 8 | 季报数值是单季还是累计不确定，直接算同比可能用错口径 | 文档未说明 | 用“Q4 季报值 = 年报值”自动判定口径（实测为累计值），判定结果显示在页面上；判定不出时标注“按惯例推定” |
| 9 | 大智慧 PE 为负，拉低同行中位数 | 亏损公司 PE 没有意义 | 中位数只取正值，并注明参与计算的家数 |
| 10 | 想展示“估值分位”，但接口没有历史估值 | — | 不推算，列为待验证问题，并给出重建方法 |
| 11 | 用户问“现在能买吗？” | 合规风险 | 规划器标记合规并改写问题，规则兜底 LLM 的漏判；实测线上提示为“不提供任何买卖或涨跌判断建议，改为呈现客观维度…” |
| 12 | **线上部署后几分钟，数据源连接超时**（`UND_ERR_CONNECT_TIMEOUT`）。香港节点、新加坡节点都复现，本地同时正常 | 扶摇对云服务器 IP 的间歇性限制（推测），不在我们的控制范围内 | 不能只靠重试。① 6s 探测熔断；② 随部署打包“最近一次成功快照”，熔断后整体回退并逐条标注；③ 问答接口复用签名后的证据，数据调用减半；④ 并发从 6 降到 4，删掉一个未使用的接口调用 |
| 13 | 合规误报：“本清单**不给出**能否买入的判断”被判为违规 | 正则没有考虑否定语境 | 命中词前 8 个字内有“不 / 无 / 非 / 未 / 没有 / 避免”时不判违规（此规则已被 #20、#31 收窄为“同一分句内的固定否定短语”） |
| 14 | 第一次校验未通过后，**整篇重写超时**，最终只能带着标注输出 | 整篇重写要重新生成 40 多条陈述，耗时与首轮相当，加上数据采集超过 60s 函数时限 | 改为**定点修复**：只把未通过的陈述 + 校验意见 + 相关证据交给 LLM，返回逐条修复或丢弃。实测修复 1 条用时约 3s，复验通过 |
| 15 | 测试子 agent 发现：失败调用的 `attempts` 恒为最大值；`timeoutMs < 1500` 时请求从不发出 | 计数与时限下限写错 | 记录真实请求次数；1500ms 下限只作用于总时限剩余量 |

### 3.1 对抗式逐句审计后的修复（第二轮）

提交前，我们用一个多 agent 审计工作流对照题目原文逐句核查：4 个审计员分组负责，默认立场是“无法证明满足就判不满足”，另有 1 个查漏员。共核对 67 条要求，满足 39 条、部分满足 26 条；不满足的 1 条是可选的演示视频。以下是据此做的修复：

| # | 审计发现 | 修复 |
|---|---|---|
| 16 | **风险维度空转**：同花顺线上风险信号为 0 条，页面不提示“已检查”；用户问风险时，LLM 拿不到估值和行情证据，写出了“清单没有估值证据”这种与看板矛盾的结论 | 新增风险规则清单（14 项，含 3 项数据风险），全部检查，未触发的项折叠展示；解读时始终提供负面证据、非正常证据，以及风险规则和矛盾所引用的证据；提示词要求覆盖已触发风险，不得声称“没有某类证据” |
| 17 | **快照模式下矛盾和风险被静默清空**：规则只认 `ok` 状态 | `stale` 证据也参与判定，并标注“基于快照/过期数据”；解读区顶部和概述前确定性加上快照提示 |
| 18 | **同行口径冲突被当成正常结果**：东方财富营收 22.80 亿、归母净利 80.64 亿（净利率 353.8%），同花顺“营收第 1”被判为正面 | 合理性检查生成冲突证据 X2 和待验证问题；不可比的同行只从依赖营收的排名（I1/I3/I4）中剔除，净利润排名（I2）保留它；存在剔除时排名不判正负 |
| 19 | **字段为空时算出假值**：负债为空时资产负债率算成 0.00% 并判正面；只送股也被算作“有现金分红” | 逐字段 `isNum` 检查，走 missing；分红只统计每股派现 > 0 的年份 |
| 20 | **合规漏洞**：“后市看涨”“建议逢低布局”“不建议卖出，可继续持有”都能通过；规划器的文字不过校验 | 扩充词表（含好坏标签词）；否定豁免收窄为固定短语；规划器文字也过校验；修复后仍违规的句子隐去原文 |
| 21 | **事实/推断由 LLM 自报，不校验**：出现“+5.5%，市场环境偏平”被标成事实 | 含评价性措辞的“事实”确定性改判为推断，并在页面注明 |
| 22 | **业务错误也回退快照**：key 失效（2003）时页面不再显示“调用失败”，与 README 矛盾 | 只有网络、超时、限流、上游 5xx 等可恢复错误才回退；实测 key 失效时 20 个调用如实显示为 2003 失败，正负结论为 0 |
| 23 | 单位、时点、口径不全：PE 没写“倍”；异动只写“当日”；“两市成交额”用深证成指，名不副实；上年同期“披露日”是今年的日期，没有说明 | 估值加“倍”；抽屉新增“单位”行和“数据时点”列；改用深证综指（实测与深证成指成交额相差约 0.001%，主要是改正口径名称）；披露日加脚注，F1/F2 口径中注明“可能为追溯调整后的比较数据” |
| 24 | 无法从结论钻取到“待验证问题” | 抽屉新增“相关待验证问题”（含原因、验证路径、跳转、追问按钮）；待验证问题本身也可以一键追问 |
| 25 | 文档与实现不一致：LLM 切换顺序、调用次数（25 vs 24）、“零信任”“不静默删除”等措辞夸大 | 统一改为与代码一致；修复时删掉的陈述会计数并说明原因；措辞改为如实描述正则校验的局限 |
| 26 | README 缺“产品选择” | 新增一节，说明为什么选这道题、为什么选同花顺、为什么用茅台对照 |
| 27 | 复核时线上“现在能买吗？”降级成了模板输出：DeepSeek 返回空内容，备用的 GLM 和 Kimi 只分到约 8 秒，全部超时 | 三家都是推理模型，默认推理过长；用完整提示词实测，GLM、Kimi 超过 55 秒 | 三家统一设 `reasoning_effort: low`。实测完整提示词：DeepSeek 19 秒、GLM 26 秒、Kimi 46 秒，均能完成。空输出时记录响应片段以便复盘。之后线上连续 3 个问题都走 LLM 路径并通过校验（40 秒、23 秒、15 秒） |

### 3.2 第二轮对抗式复核后的修复

修完第一轮后，我们重新部署并再跑了一轮对抗式复核。4 个审计员逐条确认上一轮的问题，并专门寻找修复引入的新问题。复核确认上一轮的核心问题都已修复，同时又找到以下更深的边角问题：

| # | 复核发现 | 修复 |
|---|---|---|
| 28 | LLM 规划不稳定：问“主要风险有哪些？”时偶尔漏选“经营质量”，回答写出“现金含量、负债率对应证据未出现在清单中”（实际存在） | 规则命中的维度必须保留，LLM 只能排序或追加；解读时提供**全部**风险规则（含未触发）所引用的证据；校验器新增 `false_missing_claim`：声称“未提供/无法评述”但所引证据并未缺失，判为严重问题 |
| 29 | 字段为空的问题没修干净：F3 用 null 参与运算并判正面；F5 显示 −100%；Q2 全是“--”却标为正常；M4 成交额缺失时出现 NaN；深证成交额全空时 D1 只用沪市数据算出 r=−0.94 | 每个派生计算都先检查字段；任一交易所成交额缺失超过 10% 时 D1、D2 不计算；补充 4 个回归测试 |
| 30 | 合规词表仍有漏网：“可以考虑加仓”“具备安全边际”“后市看好”“是不错的买点”“建议观望”“估值洼地”等 17 种说法能通过；“并非”豁免会放行“这并非卖出时机” | 扩充词表（持仓、建仓、观望、追高、买点、安全边际、性价比、看好、有望修复、优秀公司、前景广阔……）；删除“并非”豁免 |
| 31 | 否定豁免窗口为固定 8 个字，“本产品不提供买入、持有或卖出建议”中的“卖出”被误判 | 豁免作用域改为同一分句内、命中词之前（最多 20 个字） |
| 32 | 规划器兜底时用“理解为：+用户原句”替换意图，替换后仍含“买入”；违规原文仍保留在 API 响应的 `issues[].text` 中 | 意图改用固定文本；校验报告和轨迹返回前去掉原文，只保留位置、类型和原因 |
| 33 | 事实/推断改判只认评价词：因果、比较类措辞（“主要来自”“弹性”），以及引用派生或观点证据的陈述，仍显示为“事实”；LLM 漏填 type 时前端默认显示为“事实” | 改判词表加入因果、比较类措辞；引用派生或观点证据的陈述一律改判为推断；type 缺失时按推断处理；模板兜底时派生、观点类证据也标为推断 |
| 34 | 文案与计算不一致：X2 规则写“不参与 I1–I4 排名”，但 I2 实际纳入了东方财富；同行表标签也写“不参与排名” | 规则和标签都改为“只从营收类排名（I1/I3/I4）中剔除，I2 仍纳入” |
| 35 | 时点：估值和异动显示 2026-10-11（周日），容易被误读为当日数据；Q7 报告期显示接口参数“2026-2” | 统一显示“接口时点（最近交易日 2026-10-09）”；Q7 显示“2026中报”；页头和行情统计补上“元”；D1 单位改为“无量纲” |
| 36 | 上游 HTTP 5xx 但没有标准信封（如返回 HTML）时，既不重试也不回退 | 归类为 `HTTP_5XX`，纳入重试和快照回退 |
| 37 | 已签名证据超过 30 分钟后，问答接口会重新采集，可能超过函数时限 | 前端在 25 分钟时先刷新证据；服务端按已耗时扣减 Agent 的时间预算 |
| 38 | D1 仅 r=0.50（低于 0.6 强相关线），但公司类型仍写“顺周期” | 显示为“轻资产金融信息服务（顺周期属性待验证）” |

### 3.3 第三轮：复核中“查漏员”发现的修复副作用

第二轮修复后，查漏员专门检查了“修复是否引入新问题”，发现如下：

| # | 发现 | 修复 |
|---|---|---|
| 39 | **合规词表扩成单个词后误伤正常陈述**：“持有货币资金”“业务布局”“股价近 1 月反弹”“高估值意味着……”都会被隐去，受影响最大的是“沿证据继续研究” | 改为**短语级**匹配：只拦“继续持有、建议观望、将反弹、有望见底”这类操作建议和预测；8 句中性陈述和 6 句违规陈述都写进了回归测试 |
| 40 | 非买卖类问题的规划意图命中词表时，也被改写成“买卖或涨跌问题”，与合规标记矛盾 | 只有被判为买卖类问题时才用固定文本，其他情况只隐去命中的词 |
| 41 | `false_missing_claim` 误伤正当的“未知”陈述，例如“历史估值分位未提供” | 只检查事实和推断类陈述；涉及历史、分位、分部、原因、公告等证据之外信息的陈述豁免 |
| 42 | 事实/推断改判会命中证据原文中的词，例如规则里的“估值偏高”，把确定的事实降级成推断 | 先去掉与所引证据标题、取值、口径、规则重合的片段，再匹配评价词；“来自”“驱动”只在因果句式中算评价 |
| 43 | 快照提示在横幅和概述里重复出现，且没有说明比例 | 解读区只保留一处提示，写明“全部/大部分/部分（n/总数）”；区分“实时失败用快照”和“K 线较旧”两种原因 |
| 44 | R3 用 \|r\| 判断，负相关也会被说成“顺周期” | R3 改为 r ≥ 0.6；新增 R93：r ≤ −0.6 时作为数据风险提示与预设相反 |
| 45 | 茅台没有“经营驱动”维度，R3/R4 却显示“相关证据不可用，无法检查”，像是数据失败 | 标为“该公司类型不适用” |
| 46 | LLM 不可用时，模板里的“风险”维度为空，风险被放进“未知”区 | 模板把已触发的风险规则填入风险维度；没有触发时写“已检查 15 项，均未触发” |
| 47 | 抽屉“数据时点”仍显示周日的接口日期 | 估值、异动来源加注“对应交易日 X” |
| 48 | 目标公司自身字段为空时，排名证据会静默消失 | 走 missing，写明原因 |

## 6. 我对 AI 的信任边界

- **数字：不让 LLM 生产数字**。所有数字由代码计算，LLM 只能引用；校验器用正则把陈述中的数字和所引证据比对。它能拦住编造的数字，但有局限，例如识别不了中文数字。
- **方向与判定：低信任**。正负判定由公开规则完成，LLM 复述时需与规则一致，有异议时只能以“推断”形式提出。
- **推断：有限信任**。必须标注置信度，用徽标与事实区分；LLM 把推断标成事实时，由规则改判。
- **合规：提示词约束 + 规则拦截**，覆盖规划和解读两个阶段的文字。规则词表是经验性的，可能漏报，漏报只能靠提示词兜底。
