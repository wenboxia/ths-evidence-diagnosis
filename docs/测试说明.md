测试过程中发现并修复的 bug（由测试子 agent 报告）：
1. 失败调用的 `attempts` 一律显示为最大值，与实际请求次数不符，复盘时会误导 → 改为记录真实请求次数。
2. `timeoutMs < 1500` 时调用从未发出 → 1500ms 的下限只用于总时限剩余量。

## 4. 合规与极端输入

| 输入 | 处理 |
|---|---|
| “能买吗 / 会涨吗 / 目标价多少 / 明天涨不涨” | 规则正则识别（LLM 漏判时兜底）→ 合规提示 + 改为客观维度 |
| LLM 输出含“建议买入 / 目标价 / 必涨”等 | 校验器 `compliance` 判为严重问题 → 重写；仍未通过时在原句旁标注“⚠ 未通过校验” |
| 超长问题 | 服务端截断为 300 字 |
| 空问题 | 按公司类型的默认优先级做全面诊断 |
| 非 POST 访问 `/api/ask` | 405 |
| XSS（问题或 LLM 输出中带 HTML） | 前端所有动态文本经过 `esc()` 转义 |

## 5. 已知未覆盖

- 没有对 LLM 推断的**逻辑正确性**做自动化评测（需要人工标注集，见 README“未做事项”）。
- 前端没有自动化 UI 测试，靠第 3 节的人工验收。
- 没有压力测试；扶摇限流策略是动态的，大并发下的表现未验证。
